# 工作流产品需求

## 1. 产品概述

这是一个面向理工类文献，重点是物理论文的论文理解工作流。产品目标不是复现论文代码，也不是做通用文献管理，而是把一篇论文从“拿到 PDF”推进到“真正读懂”的全过程标准化、自动化和可复用化。

产品将以双层结构实现：
- 上层：VS Code 及其 Claude Code 插件中的 System Prompt 或 Skill 模板，负责约束阅读方式、输出结构、路由规则和质量标准。
- 下层：最小可用脚本链路，负责把 PDF 转换为可阅读、可检索、可追溯的中间产物。

## 2. 项目目标

### 2.1 总目标

帮助用户快速、系统地理解理工类论文，尤其是物理论文中的公式、图表、推导和结论，让用户能够从一篇论文中获得结构化的学习成果，而不是只得到原始提取文本。

### 2.2 具体目标

- 从 PDF 中稳定提取正文、图注、公式和表格等信息。
- 自动形成适合深度阅读的 Markdown 中间稿。
- 将论文组织成可问答、可回溯、可复盘的知识结构。
- 生成面向学习的结果，而不是面向复现或开发的结果。
- 支持单篇论文分析和批量论文分析两种模式。

## 3. 使用场景与目的

### 3.1 主要使用场景

- 物理论文精读前的快速判断：这篇文章值不值得读。
- 论文初读：先看摘要、结论、图表和公式结构，建立整体认知。
- 论文精读：逐节理解方法、推导、假设和结论。
- 图表理解：解释实验图、谱图、趋势图、示意图的物理意义。
- 公式理解：补全作者省略的中间推导，解释每一步用了什么条件或近似。
- 批量阅读：对某个文件夹下的一批相关文献进行连续分析。

### 3.2 使用目的

- 降低理解论文的门槛。
- 缩短从“看不懂”到“能复述”的时间。
- 将论文阅读过程标准化，减少重复劳动。
- 能对使用者的问题进行回答并进行原文定位。
- 把零散的理解结果沉淀成可复用的学习资产。

### 3.3 领域范围

当前优先面向理工类，重点是物理论文。后续可扩展到材料、化学、计算机科学中的理论和实验论文，但第一版不以通用化为目标。

## 4. 使用者

### 4.1 主要使用者

- 需要理解物理论文的学生。
- 需要快速把握论文贡献的研究者。
- 需要把一篇论文读透的自学者。
- 需要批量整理领域论文的研究助理或知识整理者。

### 4.2 使用者特征

- 有明确的文献阅读任务。
- 希望得到结构化结果，而不是纯摘要。
- 能接受以 Claude Code 为主的对话式工作流。
- 希望系统能自动处理中间步骤，但仍保留人工可读性。

## 5. 核心功能

### 5.1 单篇论文分析

用户通过指定 PDF 文件名发起任务，系统对该论文进行完整分析。

输出应包括：
- 一页纸结构化总结（必需，先生成）。
- 论文研究问题、方法、核心贡献和局限。
- 章节级精读笔记。
- 关键符号和术语对照表。
- 公式推导补全记录（按需，或用户显式要求时生成）。
- 假设与近似清单。
- 论文理解中的关键问题与回答。

### 5.2 批量论文分析

用户显式指定目录后，系统对目录下所有文献逐篇处理。

要求：
- 每篇论文独立输出。
- 批量模式必须显式触发，不能默认开启。
- 各篇结果互不覆盖，互不混淆。

### 5.3 PDF 提取与清洗

系统应将 PDF 转换为适合阅读和检索的中间格式。

要求：
- 图片型论文优先使用 MinerU 提取。
- 文本型文档可结合 pdfplumber 等库补充提取。
- 提取后需清洗 Markdown，保留图注、公式、章节结构和引用线索。
- 保证中间结果尽量可追溯到原文。

### 5.4 公式理解与推导补全（公式填坑）

系统需要支持对跳步推导的解释。

具体能力：
- 识别论文中“显然可得”“容易得到”“经过简单推导”等省略步骤。
- 将中间推导补齐成可读的分步说明。
- 标明用了哪些数学技巧、边界条件、近似或物理假设。
- 如果某一步无法可靠补全，应明确说明不确定性。

### 5.5 图像理解路由

Markdown 中如果存在图片，系统必须正确处理。

规则：
- 如果当前环境有可用的多模态副模型，交给多模态模型分析图片，再由主模型整合结论。
- 如果没有多模态能力，只能基于图注和正文上下文解释，不得臆测图像细节。
- 必须明确说明当前是“看图解释”还是“基于图注和正文推断”。

### 5.6 PageIndex 问答

系统需要构建论文的索引结构，以支持后续问答和定位。

能力包括：
- 根据问题定位到相关章节、公式或段落。
- 支持对论文内容进行追问。
- 支持“这篇论文到底在讲什么”的概括性追问，也支持“公式 3 怎么来的”这种局部追问。

### 5.7 质量控制

系统应在流程中设置基础质量闸门。

例如：
- clean_md 低于阈值时提示提取失败并进入降级链路。
- 图注缺失时提示图像理解可能不完整。
- PageIndex 构建失败时直接中止并报告原因。
- 输出内容必须尽量可追溯，不能只给结论不说明来源。

## 6. 工作流形式

### 6.1 产品形态

本产品采用“双层结构”：

1. System Prompt 或 Skill 模板。
2. 最小可用脚本链路。

### 6.2 设计原则

- 先稳定，再扩展。
- 先做理解，不做复现。
- 先保留可追溯性，再追求自动化程度。
- 先支持单篇，再支持批量。
- 先让流程能跑通，再优化体验。

### 6.3 推荐执行口令

- 单篇分析：分析论文：指定文件名
- 批量分析：批量分析：指定目录

系统默认行为：
- 单篇模式下必须指定文件名。
- 批量模式下必须显式声明目录。
- 不允许无目标地泛泛分析。

## 7. 输入与输出规则

### 7.1 输入规则

- PDF 文件必须放在 projects 目录下。
- 用户必须提供明确文件名或明确目录。
- 如果同名文件存在多个位置，必须让用户进一步澄清。

### 7.2 输出规则

每篇论文输出目录统一使用：
- outputs/<pdf_stem>/

目录名规则：
- 以 PDF 文件名去掉扩展名后的 stem 作为主目录名。
- 如果目录重名，则自动追加时间戳，避免覆盖。

建议输出内容：
- raw_md：MinerU 原始提取结果。
- clean_md：清洗后的 Markdown。
- pageindex：PageIndex 索引结果。
- summary：最终阅读结果。

### 7.3 多 PDF 输出策略

当批量分析多个 PDF 时：
- 每篇论文都独立输出到自己的目录。
- 目录命名继续采用 stem 规则。
- 若 stem 重复，使用时间戳区分。
- 不在同一个目录里混放不同论文的结果。

## 8. 最小可用脚本链路

### 8.1 处理链路

MinerU/pdfplumber 提取 PDF → Markdown 清洗 → PageIndex 构建 → 一页纸总结 → 公式推导补全 → 生成学习结果

### 8.2 脚本职责

- 参数解析：识别单篇或批量模式。
- 路径检查：确认 PDF 文件或目录存在。
- 调用 MinerU：生成原始 Markdown。
- Markdown 清洗：整理结构、路径和图注。
- PageIndex 构建：建立索引，支持问答。
- 一页纸总结：调用结构化总结能力输出结果。
- 公式推导补全：按需调用数学推导能力。
- 结果写入：保存到 outputs/<pdf_stem>/。
- 失败报告：记录失败原因与可重试步骤。

### 8.3 允许的复杂度边界

- 只做工作流必须的事情。
- 不做额外抽象，不做过度通用化设计。
- 不在第一版加入复杂的插件调度、可视化面板或网络服务。

## 9. 关键输出内容

### 9.1 输出顺序与必需性

- 顺序：clean_md + PageIndex → 一页纸结构化总结 → 章节笔记/符号表 → 公式推导补全 → 追问清单。
- 必需：一页纸结构化总结、章节级理解笔记、关键符号与术语表、追问清单。
- 按需：公式推导补全（出现明显跳步或用户显式要求时生成）。

### 9.2 一页纸结构化总结

系统应首先输出高质量的一页纸结构化总结，采用以下标准结构：

| 模块 | 内容要求 |
|------|----------|
| 动机 | 要解决什么问题？现有方法的不足？研究背景和意义？ |
| 方法 | 核心思路、关键创新点、技术路线、实验设计？ |
| 结果 | 主要实验结论、对比基线的优势、关键数据？ |
| 意义 | 学术贡献、应用价值、局限性、未来方向？ |

**实现方式：** 使用 `academic-researcher` skill 生成结构化总结，确保每个模块都有实质内容，并引用原文关键句作为依据。

**输出格式：**
- Markdown 格式，便于阅读和复用。
- 每个模块 2-3 句话，总计一页纸篇幅。
- 保留原文引用，支持追溯。

### 9.3 章节级理解笔记

- 每个一级标题至少 3 条要点。
- 要点需包含“结论 + 来源”两部分。

### 9.4 公式推导补全（公式填坑）

- 输入：公式块 + 相邻上下文段落。
- 输出：分步推导，标注使用的假设或近似。
- 不能可靠补全时需明确说明不确定性。
- 实现方式：优先使用 `math-reasoning` skill；不可用时输出“待补全”并说明原因。

### 9.5 关键符号与术语表

- 表格格式：符号/术语、含义、单位（如有）、出处。

### 9.6 可继续追问的问题列表

- 3-8 条问题，覆盖动机、方法、假设与结论。
- 每条问题附定位线索（章节或公式）。

### 9.7 输出文件建议

- outputs/<pdf_stem>/summary/one-pager.md
- outputs/<pdf_stem>/summary/section-notes.md
- outputs/<pdf_stem>/summary/formula-notes.md
- outputs/<pdf_stem>/summary/glossary.md
- outputs/<pdf_stem>/summary/followups.md

## 10. 需要考虑的因素

### 10.1 可追溯性

所有重要结论都应尽量对应到原文中的章节、段落、公式或图注。

### 10.2 不确定性表达

当系统无法可靠判断时，要明确说明不确定，而不是强行解释。

### 10.3 人工可控性

用户应能通过文件名、目录名和口令控制分析对象，避免系统自行猜测。

### 10.4 可扩展性

第一版不追求一次性覆盖所有功能，但要给后续扩展留出空间，例如后续可以增加：
- 更强的图像理解。
- 更细的概念图谱。
- 更强的跨论文对比能力。

### 10.5 兼容 Claude Code 的使用方式

文档和脚本都应适合在对话式环境中直接触发和执行，用户不需要学习复杂命令。

### 10.6 质量指标（建议阈值）

- clean_md 少于 800 字则判为提取失败并进入降级链路。
- 一页纸总结四个模块齐全，每个模块至少 2 句话。
- 章节级理解笔记覆盖一级标题的比例不低于 80%。
- 公式推导补全包含“假设/近似”或“无法补全原因”。

### 10.7 错误处理与回退

- PDF 提取失败：记录失败原因，尝试降级提取；仍失败则输出失败报告。
- 公式无法补全：保留原公式并标注不确定性原因。
- 批量处理部分失败：继续处理其余论文，并输出 failure-summary.md。

## 11. 验收标准（量化）

### 11.1 量化指标

- 单篇流程从输入到输出可完整跑通，并生成 outputs/<pdf_stem>/ 目录。
- 一页纸总结四模块齐全，且每模块不少于 2 句话。
- PageIndex 能定位至少 3 个问题的答案片段。
- 章节级理解笔记覆盖一级标题不少于 80%。

### 11.2 测试场景

- 单篇论文（文本型）：能输出 one-pager、section-notes、glossary 与 followups。
- 单篇论文（公式多）：能输出 formula-notes 或明确的无法补全原因。
- 批量目录：至少 1 篇失败时，其余论文仍可完成，并生成 failure-summary.md。

## 12. 实施准备与交付物

### 12.1 实施前置条件

- MinerU 已可用（本地可调用）。
- PageIndex 可构建索引（可用脚本或库）。
- Claude Code 可调用已安装的相关 skill（academic-researcher、math-reasoning）。

### 12.2 数据契约（实施必须遵守）

- clean_md 作为后续所有生成的唯一输入源。
- PageIndex 索引必须可映射到章节路径与原文来源。
- 所有输出文件命名固定，路径固定为 outputs/<pdf_stem>/summary/。

### 12.3 交付物清单（第一版）

- CLI 脚本入口（支持单篇/批量）。
- Markdown 清洗脚本。
- PageIndex 构建脚本。
- 一页纸总结输出（one-pager）。
- 公式推导补全输出（formula-notes）。
- 失败报告与批量失败清单。

## 13. 里程碑与实施顺序（建议）

### 13.1 里程碑

- M1：PDF 提取与 clean_md 稳定生成。
- M2：PageIndex 构建与基础查询通过。
- M3：一页纸结构化总结输出稳定。
- M4：公式推导补全按需触发稳定。
- M5：批量模式与失败恢复稳定。

### 13.2 实施顺序

先单篇链路跑通，再接入批量与容错。

## 14. 非目标

第一版不做以下内容：

- 论文代码复现。
- 实验自动重跑。
- 通用知识库平台化。
- 复杂前端界面。
- 强行统一所有领域论文的分析模板。

## 15. 后续迭代方向

在第一版跑通后，可以逐步增加：

- 更好的论文类型识别。
- 更强的多模态图片理解。
- 更强的概念总结和跨论文对比。
- 更细的章节级学习记录。
- 更智能的批量文献管理。

## 16. 备注

本产品以“帮助使用者分析并理解论文”为唯一核心目标，所有设计都应围绕这个目标展开。任何不能直接服务于此功能的，都不应在第一版中优先加入。
